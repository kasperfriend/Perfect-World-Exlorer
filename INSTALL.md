# Install the GitHub Actions workflows

Copy `.github/workflows/pr-checks.yml`, `.github/workflows/manual-release.yml` and the root `.gitignore` into the corresponding paths in the repository, then commit them to `main` (or add them via a pull request). Keep the leading dots in the names. The PR workflow runs on PRs, pushes to `main`, and manual dispatch. Its Windows job uploads an executable and SHA-256 checksum as a workflow artifact, while the Linux job checks formatting, compiles all binaries, and runs the viewer tests. Download the artifact from the workflow run summary. Fork-PR artifacts are for review; only run binaries from PRs you trust. These are automated build and unit checks, not a full game or GPU validation.

To make a release: on GitHub go to Actions → Manual Windows release → Run workflow. Choose a trusted branch/commit using the branch selector, enter a new tag such as `v0.1.0-beta.1`, choose whether it is a prerelease, and run. Once checks and the Windows build pass, the workflow creates the tag at the exact selected commit and publishes a release with the EXE and checksum. Do not use an existing tag. Manual workflow files must already exist on the default branch for GitHub to offer Run workflow; make sure Actions are enabled and the repository/organization allows the workflow to grant `contents: write` to GITHUB_TOKEN. The dispatching user must have sufficient repository access. On cancellation or publication failure, inspect existing tags/releases before retrying. The executable still requires a trusted client and runtime DLL and is not visual parity-verified.

If uploading in the GitHub web UI, hidden directories may be awkward: use Add file → Create new file and enter `.github/workflows/pr-checks.yml` (and then `.github/workflows/manual-release.yml`), pasting their content. Create `.gitignore` at the repository root similarly. Or clone the repository and copy these files, then `git add .github/workflows .gitignore`, commit and push.

Required-check enforcement is optional and configured separately in Settings → Rules → Rulesets (or branch protection): require the desired PR job checks before merging. Actions does not enforce that automatically. Confirm the jobs complete successfully in this particular repository before enabling the rule.
