## P3.01 — container/format coverage

Census published: **`Findings/Phase-3-Agent-A-bmd-corpus-census.md`**
(regenerated by `bmd-corpus-census google_drive <out>`; ~6 s for 34,249
archive members). Headline results:

- litmodels.pck: 28,858 members, ALL MOXB BMDs, 0 read errors. Model
  versions: 100% 0x10000002. Meshes: 68,362 = 44,376×v4 + 23,986×v5;
  **zero v1/v2/v3**. 8,062 files carry chunk tag 0x80000001 (flag byte@8:
  0×7,943 / 1×119). v5 material names all `"material: "`; two-sided 2,579.
- building.pck: 5,391 members = 5,355 dds + 10 bmp + 26 tga.
- `bmd::Model::parse` succeeds on all 28,858 files — the renderer covers
  every version the census finds; the remainder are named errors.

Version acceptance now mirrors the client exactly:

| input | client behavior (address) | this renderer |
|---|---|---|
| model 0x10000001 / 0x10000002 | identical header layout (0x7bb3de / 0x7bb58b) | accepted (v1 newly) |
| other model version | log `"A3DLitModel::Load(), Wrong version!"` (0x7bb79e → 0x98ee20), FALSE | error naming version + client string/address |
| mesh v4 / v5 | 0x7ba573 / 0x7ba7a7 | implemented |
| mesh v1 | silent FALSE (0x7baa64) | named error mirroring the silent rejection |
| mesh v2 / v3 | 0x7ba0b8 / 0x7ba30d, zero corpus occurrences | named error (layout recovered, deliberately not implemented untested — see census) |
| other mesh version | log `"Unknown version [%x]!"` (0x7baa51 → 0x98ed90) | error reproducing the message format |

Trailer (the bytes after the last mesh) fully decoded and **byte-exact on
all 28,858 files** (census case count: 0): container loader 0x64e200 reads
u32 group count (0x64e307), then 0x64dd30 reads count×[u32 n][n×u32 ids]
(343,438 ids; NOT mesh indices — 303,963 exceed the file's mesh count, max
id far beyond), then 0x64e010 reads count light-group records via 0x72a0a0:
[48 B][u32][u32 m][m×17 B: 12 B direction (normalized at 0x72a1cc) + f32 +
1 B flag]; 7,455,305 light records total, flag byte histogram {0: 2,605,677,
1: 4,849,628} — binary only. This is scenery light-attachment data (lane of
Agent 3-B); `bmd::Model::parse` stops after the meshes exactly like
A3DLitModel::Load (ends 0x7bb795), and the census accounts for every trailer
byte.

Also documented from the loader: the model loop IGNORES per-mesh Load
results (no `test al,al` after the 0x7ba070 call at 0x7bb653) and merges a
new mesh into an existing one when texture handles (+0x114) match and the
material float block (+0x21c) compares equal (scan 0x7bb664, comparator
0x7b64a0, geometry-preserving buffer merge 0x7b9600) — load-time draw-call
batching; merging preserves geometry, so per-mesh reconstruction is
pixel-identical; batching itself is view-submission lane and not replicated.

## P3.03 — texture reference resolution

Implemented in `src/texture_resolution.rs` + `src/objects.rs`, in client
order (addresses in the module docs):

1. Mesh-level skips (A3DLitMesh::LoadTexture 0x7b9880): byte length ≤ 4
   (0x7b9948) or name contains `nrf_` (0x7b99c8) → success without loading.
   Corpus: 0 references hit either skip.
2. Texture-manager cache keyed by lowercased name (0x77c160) → resolver
   cache (36,274 hits in the world run).
3. `.sdr.` names (0x77c2e4): truncated after `.sdr` (0x77c2f7) and looked up
   in the runtime shader-texture registry (0x785d30); a miss is TERMINAL —
   FALSE with no file fallback (0x77c320), and the mesh load aborts
   mid-stream (0x7ba844) without resynchronizing the file position. The
   registry is populated at runtime by the effect system (outside this lane),
   so it cannot be reproduced from staged assets. Documented approximation:
   the registry objects' source pixels are the same-named archive members
   (all 4 world `.sdr.` names exist in building.pck), so the full name is
   resolved as a file and EVERY occurrence is recorded as a
   `shader-registry-file-backed` register row (4 distinct names, 45 refs).
   This is the explicit handling of the only animated/procedural texture
   class reachable from a BMD reference — the BMD format itself carries no
   frame lists (single 256-byte name per mesh; census-verified).
4. VFS archive-first (AFileImage::Init 0x76d810 → 0x771970): mounted
   archives scanned in mount order; an archive participates when its mount
   tag is a `strstr` substring of the lowercased query, then exact
   normalized-member lookup. Mount order of litmodels.pck vs building.pck is
   not recoverable from the exe alone and unobservable in this corpus (0
   references exist in both archives; litmodels.pck holds no texture members
   at all) — implemented and tested anyway.
5. Disk fallback: plain `fopen(name, "rb")` relative to the working
   directory (0x76d878) — no directory prefixes are appended by the client.
6. Final miss classification: names containing `Textures` or `Tex_`
   (case-SENSITIVE `strstr`, 0x76d88d/0x76d8a6) fail SILENTLY; anything else
   logs `"AFileImage::Can not open file [%s] from disk!"` (0x986f28). Both
   corpus-missing names contain lowercase `textures`, so the client would
   log them — reproduced literally (`missing_quiet = 0`, rows registered).
7. nrf derivation (0x7b98e8–0x7b9944): basename via GetFileName (0x76ee80),
   `shaders\textures\nrf\%s` (0x98ed38), FileExists (0x76f1e0) failure →
   `shaders\textures\nrf\rf_default.dds` (0x98ed14). All 39,416 world refs
   derive; shaders.pck is unstaged so all take the fallback, which is also
   absent — tolerated exactly like the client (A3DTexture::Load returns TRUE
   on open failure, 0x78a440); rows registered per distinct name.

Resolution-order tests with duplicated/shared/missing references
(`src/texture_resolution.rs`, all passing): `archive_wins_over_disk_and_mount_order_decides_duplicates`,
`shared_references_resolve_identically_and_hit_cache`,
`missing_references_report_and_quiet_flag_matches_client_strings`,
`disk_fallback_uses_plain_fopen_semantics`, `shader_registry_names_are_rejected_by_name`,
`shader_registry_file_backed_lookup_bypasses_registry_cache`,
`trivial_names_never_reach_file_lookup`, `nrf_derivation_and_default_fallback`.
Whole-corpus reference census: 68,362 refs / 4,156 distinct; 4,154 resolve

## P3.08 — bounded residency

Measured numbers, methodology, and limitations:
**`Findings/Phase-3-Agent-A-residency.md`**. Summary: full-world preload
(16,037 placements) with a 256 MiB decoded-texture budget — peak residency
259.6 MiB against ~1.70 GiB cumulative decode traffic, 4,135 LRU evictions,
0 pinned-over-budget events; content-hash dedup recorded 41 alias hits
(9.36 MB of duplicate resident copies avoided) and reduced the whole-world
page count from a measured 66 to **65** (atlas base 4,144.0 → 4,090.0 MiB,
with mips 5,525.2 → 5,453.3 MiB; baseline re-measured from commit 8e2d005 on
the same machine and data).

Acceptance tests (passing): `objects::tests::lru_eviction_keeps_residency_inside_the_byte_budget`
(eviction happens, budget holds, alias names of evicted content disappear),
`objects::tests::pinned_batch_entries_survive_over_budget`,
`objects::tests::touching_a_reference_pins_its_content_again`,
`objects::tests::dedup_stores_identical_content_once_under_alias_names`,
`world_objects::page_tests::content_dedup_reduces_page_turns` (dedup reduces
page turns), `world_objects::page_tests::missing_references_share_one_fallback_slot`.

## Remaining unsupported cases (all explicit, all registered)

- Mesh versions 0x10000002/0x10000003: layouts recovered from the client
  (0x7ba0b8/0x7ba30d) but zero corpus occurrences → named parse errors
  instead of untested code paths. Mesh 0x10000001: named error mirroring the
  client's silent rejection.
- `.sdr.` shader-registry textures: runtime registry unreproducible from
  staged assets; file-backed approximation with per-occurrence register rows.
- PSD textures (865.psd): no decoder; register row + neutral fallback swatch
  (unchanged pre-existing behavior).
- textures.pck / shaders.pck: not stageable through the available download
  path (>100 MiB, no split parts); documented in the residency findings; any
  reference that would resolve there surfaces as a register row (none found).
- BMD trailer light data: decoded and byte-accounted by the census, not
  consumed (Agent 3-B lane).

## Interface changes for other agents

- `world_objects::Message::Done` now carries `stats: DoneStats` (residency +
  resolver counters, unresolved-row count, page count). Consumers in
  `gpu.rs` and `world-preload-check.rs` updated; no other agent code touched.
- New `Objects` API (additive): `texture_key(&str) -> Option<u64>` (content
  hash for cross-name dedup), `unresolved() -> &[UnresolvedTexture]`,
  `residency() -> ResidencyStats`, `resolver_stats() -> ResolverStats`.
  `texture()`, `update()`, `load_ids()`, `get()` signatures unchanged.
- New module `crate::texture_resolution` (resolver + `normalize` +
  `MountedArchive`); bins embedding `objects.rs` must embed it too (done for
  all 4).
- `PW_TEX_BUDGET_MIB` env var controls the residency budget (default 256).
- 3-B: the trailer grammar in `Findings/Phase-3-Agent-A-bmd-corpus-census.md`
  + `bmd.rs` module docs is the entry point for scenery light attachments
  (loader 0x64e200 → 0x64dd30/0x64e010 → 0x72a0a0).
