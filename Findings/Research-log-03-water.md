> Historical research log. Entries are chronological and describe the state at the time; later entries can supersede earlier ones. See the README and roadmap for current status. Client data and private storage details are not included.

### Water normal playback and shader vector
`A3DTerrainWater` initializes 29 normal frames at `0x7ca170`. Its update at `0x7ca5cd–0x7ca652` accumulates elapsed milliseconds, advances the frame at each 33 ms threshold and wraps by the frame count. The viewer now follows that ~30.3 Hz / 957 ms cycle rather than its earlier guessed 10 Hz, retaining interpolation between frames as a deliberate smooth-animation extension (the original client steps frames). Phase is calculated using bounded double-precision elapsed time before GPU upload to avoid long-session frame-index/precision problems. The actual `water_expensive.txt` uses decoded normal-map values directly for both bump and Fresnel dot; the viewer no longer normalizes this decoded sample. These are visible changes in the experimental water shader, not full water parity: UV scaling/scroll, edge, reflections, refraction, alpha and other water passes remain approximate. Unit tests cover frame boundaries and long sessions; a software GPU validated the WGSL pipeline, but the changed water appearance was not compared to the running game.

### Water reflection coefficient and color space (current continuation)
Retail `0x7ca8bc–0x7ca93e` computes expensive-water pixel constant c0.a per water plane as `clamp(0.23 * (camera_y - plane_y) / underwater_fog_end, 0.11, 0.23)`. The constants are the EXE's 0x8f2e38/3c. `0x4211b5–0x4211f9` feeds interpolated regional underwater fog parameters via `0x7809c0`; water object +0x6d0 is the end value, also passed to the engine fog-end setter at 0x7ca9de. The viewer applies the formula per water fragment (planes are flat) with a small positive guard for invalid/zero end distance. The existing Schlick and normal distortion are used; other passes still differ.

Water reflection/refraction source maps are now sampled via UNORM views and filtered/mixed in encoded color space, matching the legacy non-sRGB water shader arithmetic; final values are converted to linear only for an sRGB output target. This also applies to the scene-copy blit to preserve source pixels. The GPU check covers encoded blending on UNORM and sRGB targets, both reflectance clamps, and overlapping-plane depth ordering. This does not establish complete water parity: reflection/refraction content, alpha/coastline geometry, underwater treatment, animated textures, timing interpolation, pass sequencing and live appearance still need comparison. UV matrix offsets `0x7c95be/0x7c95e8` and alternate pass changes at `0x7cb595–0x7cb610` need further tracing; `0x781510/0x781eb0/0x782020` appear to deal with separate shoreline wave geometry and are not assumed to describe flat water.

### Water grid UV and terrain-only shore depth
The water geometry routine `0x7cbb20–0x7cc350` emits base UVs at `0x7cbf7a–0x7cbf8e` and `0x7cc141–0x7cc25c`: each cell has an integer-dependent UV base (`int(grid_size * 0.025 + 0.5)` times cell index) plus a 0..1 fractional coordinate across the cell. The expensive water vertex shader maps v2 into t1 by the stage-1 matrix. Construction at `0x7c95a8–0x7c95f2` gives 2x scale, initially (0.05,0) translation. In default mode 0, `0x7ca47b–0x7ca4e5` rotates that translation by elapsed milliseconds * 0.025 degrees, i.e. 25 degrees/second; constructor sets mode 0 at `0x7c9270`. The viewer now generates 0..1 cell UVs, omits the integer base because 2x scale and repeat sampling make it equivalent, and rotates the offset with a bounded double-precision phase. Frame blending remains intentionally smoother than retail. Other client modes and exact texture sampler/LOD remain to be traced.

For the edge path, `0x7cd05a–0x7cd0b9` activates water_edge shaders and passes c0 = (1, water elevation, 1/field +0x28, 0); constructor `0x7c9263` initializes that field to 0.66. `water_edge_vs.txt`/`water_edge_ps.txt` saturate `(water_y - terrain_y)/0.66`. This edge routine is conditional (`0x7ccfb0`); do not assume all water quality modes use it. The viewer now snapshots the terrain-only depth after terrain and before trees/grass/scenery, reconstructs the visible terrain hit from the inverse main view-projection, and uses that ramp above water; the full scene depth remains separate for refraction occlusion. Empty-depth pixels and below-water views deliberately use full edge coverage. This is closer to the client's height-based edge, but is still not the original edge render target/pass: occlusion, screen edges, filtering, alternative client modes, underwater handling and unloaded terrain can differ. The extra terrain-depth copy and split opaque pass have performance cost. GPU checks cover both output color formats, shore half-alpha with a different scenery depth, two reflectance bounds, and water plane ordering; no live visual comparison or Windows hardware verification was performed.

### Per-water-plane clipped refraction and authored normal mips
`0x7cc6ac–0x7cc8b5` shows the full-refraction branch selecting a separate target per water height, changing fog to regional underwater fog, enabling clip plane `(0,-1,0,water_height)` and invoking scene rendering. At `0x7cc6e0–0x7cc718`, the water-specific fog distances are `camera_y-water_y+0.01` and `camera_y-water_y+0.55*underwater_fog_end`, and the target is cleared to underwater fog color. The viewer now stores the main scene separately, renders a below-plane clipped and underwater-fogged scene to the refraction texture per visible plane when above water and reflections are enabled, then renders the mirrored reflection and water. Scene compositing and fallback retain the original main scene; per-plane target work is serialized before reuse. Below-water and reflections-off paths retain the former scene-copy approximation, not a recovered client mode. Rendering an additional scene per visible plane has substantial GPU cost, and material/grass/sky behavior, target sizes, clipping conventions and sequencing are not proven equivalent. This branch and original UI mode-selection need live inspection; not a claim of full water parity.

`0x7cab00–0x7cab26` sets D3D texture stages to filter type 2 via `0x779f60`, which applies linear min/mag and, if supported, mip filtering. The water loader now preserves DDS-authored uncompressed ARGB mip levels and uploads the common sequence chain; lower mip corruption falls back to the previously supported base image. This is conditional on the actual user archives containing those mips, which were not available for inspection in this turn. A synthetic multi-level DDS was decoded, malformed/truncated mips were rejected by the decoder, and the GPU water test exercised a mipmapped array and different scene versus refraction colors. 88 unit tests and software GPU tests passed; no full client render or physical Windows GPU validation.

### Shoreline wave records (work in progress)
Actual `world/bsdata/69.dat` contains eight version `0x10003000` shoreline records following its water mask. Client `0x782680` reads capacity, width, point count, float3 positions, then `3*point_count` ARGB day colors and the same number of night colors. The sample point counts are 52,45,41,37,40,132,286,34; first day/night colors 0xff647f94/0xff235175. The new bounded loader retains this data, and leaves the grid usable if shoreline versions are unsupported or damaged. `0x782020` generates 3 vertices per point and 4 triangles per segment, with transparent outer rows and opaque middle row; it uses width, joins, seeded noise and random variation. Geometry has NOT been ported. The executable references `textures\\water\\wave1.dds`, `shaders/vs/wavevs.txt`, and `shaders/ps/waveblend.txt`. The vertex shader calculates horizontal distance fade using sight range 400 (`c0.w`=1/160000), and samples three distinct UV matrices. The pixel shader combines three samples by successive alpha lerps, attenuates alpha by 0.6 and multiplies texture RGB by 2× interpolated authored light color. Neither the three texture transforms, generated geometry, blending/depth settings, nor this shader pass has yet been ported; do not claim rendered wave parity. Older wave versions 0x10002000 and 0x10001000 are recognized by the original client but not this parser. Tests include actual sample 69 if available and synthetic malformed-array cases; 90 main unit tests and all-bin check passed.

### Shoreline rendering implementation (still WIP)
Ported the shoreline pass, using the authored wave points, day/night per-vertex colors, and `textures/water/wave1.dds` read from the actual client installation (not embedded). The v1 format initializes both light arrays to 0x80808080; v2 loads the day colors and generates night colors at 0.3 times each channel; v3 stores both. From 0x782020, the geometry has 3 rows and 4 triangles per segment, minimum? **maximum** width 4, a mitered join, UV U = accumulated distance / 15 and V near 1/.75/.5, seeded multi-octave noise, and 0..0.10 random vertical jitter. `0x766320/0x766910` supply a Park-Miller random noise table; its 5 octaves and smoothing have been implemented. Global rand state is dependent on prior game activity; a deterministic CRT sequence is substituted and exact random starting state is not established. The three UV matrices are identity, identity plus 0.5 U, and scale 0.5; their V offsets are cubic curves constructed at 0x7c9446–0x7c950d and updated at 0x7ca67a–0x7ca6d1. Their cycle is ten seconds with phase offsets 0/2.5/0.4 s, last curve half amplitude. Client 0x7cb0ca–0x7cb0ec sets U=wrap and V=clamp, while 0x7cb0f1 disables depth writes. Implemented `wavevs.txt` distance fade and `waveblend.txt` 3-sample arithmetic. Authored BC1/BC2/BC3 mip chains are decoded including cropped 1x1/2x2 blocks; uncompressed DDS uses the water DDS decoder. Loader failures skip waves, not the whole world.

This is NOT full parity: geometry RNG phase, full-client BSData coverage and wave texture format, exact render ordering/modes, sRGB blending (the current sRGB target blends in linear rather than client encoded space), original edge-mask and underwater passes, and real game visual appearance are unverified. 95 unit tests pass, including actual sample 69 geometry, v1/v2/v3 parser, BC1 mips, curve, and synthetic GPU pass; existing UNORM/sRGB water GPU checks also pass. No original-game comparison or Windows GPU runtime test has been performed.

Follow-up: the shoreline pass now draws into a non-sRGB view of the same scene texture so alpha blending occurs in legacy encoded space, including surface, fullscreen gamma composition, and postprocess scene textures. Surface configuration requests the compatible non-sRGB view; other passes keep their existing sRGB views. A synthetic GPU test renders the same wave shader into UNORM and sRGB-backed/raw-view textures and checks encoded 0.6 alpha blending in each. This verifies the isolated blend operation, not integrated surface/view behavior on Windows or the full pass. Other shoreline and water limitations remain.

### Water edge target sequencing, additional evidence
`0x7cc9e6–0x7cc9ef` calls `0x7ccfb0` after the refraction target is established and before `0x7cb9a0`. Wrapper states examined near `0x77a3c0`, `0x77b570`, `0x77ab10`, `0x77a290`, `0x77aab0`: lighting/specular/fog and alpha blending disabled; color-write mask selects alpha. Viewer now renders terrain height ramp to refraction alpha while preserving RGB and reads that alpha in expensive water; synthetic UNORM and sRGB GPU readback checks verify alpha and depth rejection. Exact client target clearing, depth writes, culling and area subset remain unproven. Viewer currently uses the same current refraction-scene depth, no depth writes, and all visible terrain (excluding far mesh within the near bounds); these choices need independent validation.

### Below-surface refraction and containment, continuation
`0x7cca50–0x7ccd95` is a distinct below-water path. The client sets the air-fog values at `+0x6bc/+0x6c0/+0x6c4`, establishes an unmirrored camera, renders sky and geometry clipped by plane `(0,1,0,-water_height)`, restores underwater fog, and then calls `0x7cb9a0` with its below-water flag. `0x7ca890–0x7ca9bb` selects shader object `+0x44` (type 0) / `+0x48` (type 1), initialized at `0x7c9b9d–0x7c9bda` as `waterrefract.txt` / `waterrefract_scroll.txt`. Extracted `waterrefract.txt` applies normal x/z distortion of +.25, refraction RGB ×.85, and an eye-direction/negative-normal fifth-power tint between white and (0,.3,.3). `water_vs.txt` emits `eye_world - position_world` directly to t3; the shader reads t3 via `texcrd`, not the above-water normalization-cubemap `texld`. The viewer now draws a separate unmirrored clipped scene for below-water refraction and uses the recovered non-scroll arithmetic, not the above-water expensive shader; its sky uses the ordinary camera while geometry uses the alternate clip uniform. Near-vertical and grazing synthetic samples pass UNORM/sRGB GPU readback. Limitations: exact original target dimensions/clears, air fog on all object types, scrolling mode, original ps1.4 register precision/clamping and final underwater surface fog remain open. Microsoft documents texcrd outside [-8,8] as hardware-dependent: https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/texcrd---ps .

`0x780790` tests each area's strict horizontal bounds, then returns immediately based on its height and the mask test at `0x781c50`; it does not keep searching after the first bounding-box match. Viewer now rejects exact area borders consistently. All 107 areas have height == center Y; 18 pairs of area bounding boxes overlap. Client runtime height-group/insertion order is not recovered; viewer still checks all active masks and chooses the nearest qualifying water plane, so overlap behavior remains a documented difference.

### Area-class and procedural underwater texture recovery
The serialized water record byte at +44 loads directly into A3DWaterArea +0x14 (`0x781447–0x781456`). Visibility counting at `0x7cca8c–0x7ccad4` splits this bit into two area classes, and `0x7cb9a0` selects the ordinary `0x7ca870` or alternate `0x7cb4b0` material path. The world survey finds 104 ordinary areas and three alternate areas: ids 39916/39915/39917, records 71.dat 29/30/31, y=251/251.07/251 and 15/29/17 active cells. All 53,745 mask bytes are 0 or 1. The parser now retains this flag and keeps same-height batches of different classes separate, but the alternate material is NOT yet implemented and the renderer still shades them with the ordinary material. `0x7c9fe0–0x7ca087` loads 30 frames `textures/water/l/l%d.dds` for the alternate path; `0x7ca601–0x7ca652` advances them at 33ms modulo 30. `0x7cb595–0x7cb610` applies a 0.25 scale to the initial 10x UV matrix. Its fixed-function ops and color/state need a full port; do not confuse this area class with the similarly named `water_cheap.txt` quality shader.

At `0x410fc2–0x411046` the underwater bump map is generated by truncating `-32*cos/sin`, subtracting the integers from 128, and storing 8-bit R/G, then sampled as a 256x256 texture. The viewer now emulates byte quantization and half-texel bilinear interpolation in WGSL before the PS1.4 `bx2` decode, rather than evaluating an unquantized analytic sine at each fragment. A gradient-image Vulkan GPU check compares the resulting sampled pixel to a CPU reference. Exact client sampler-state selection and original D3D hardware filtering precision remain to verify.

### Alternate-area implementation (still provisional)
The three byte-flagged areas now use a separate GPU path and the actual 30-frame `textures/water/l/l0.dds`…`l29.dds` sequence loaded from the client PCK. BC1/2/3 and uncompressed DDS mip decoding is shared with shoreline waves. `0x7ca601–0x7ca652` establishes a stepped 33ms cycle. The default type-0 path at `0x7cb4b0` disables depth writes, binds the current frame at stages 0 and 1, and applies its 10x texture transform multiplied by 0.25. D3D wrappers at `0x779fc0/0x779fe0/0x77a020/0x77a040` reveal stage 0 COLOROP 13 (BLENDTEXTUREALPHA), COLORARG1 TEXTURE, ARG2 TFACTOR, and stage 1 COLOROP 18 (MODULATEALPHA_ADDCOLOR), ARG1 CURRENT, ARG2 SPECULAR. `water_vs.txt` outputs zero specular; stage 1 alpha sums texture alpha and factor alpha. The resulting UNORM pipeline applies source-alpha blending in encoded space, does not write depth and preserves the existing tree pipeline. Synthetic UNORM/sRGB GPU tests verify fixed-function color arithmetic, source-alpha blend and frame advancement. This is not yet exact: `0x7cba30` dynamically modifies the `0xa0254f55` factor when its +0x6d4 lighting pointer is non-null (world init sets it at `0x428dc6`), but the viewer currently uses the default factor. Fog, type-1/type-2 variants, transform/sampler subtlety, scene ordering and actual L-frame contents remain unverified. The source `textures.pck` is 117,047,648 bytes, above this connector's 100 MiB download limit; it was not downloaded and the genuine frame decoder has not been checked against it. The app reads the user's installed client directly.
