## Native weather/render follow-up

With the 1.4.2 executable restored, `0x7a0760` (rain update) was re-disassembled: it checks the rain-side buffer, calls the native RNG, divides its result by 100, and skips the per-tick rain generation path when the signed remainder is at least `0x28`. The accepted branch then builds randomized positions/offsets and advances a per-object slot loop. `0x79c4a0` (snow/base update) increments an object counter and dispatches through virtual active/update/reset hooks based on object state and configured thresholds. These are useful structural constraints, but they do not yet recover a complete portable particle record/lifetime model, so the deterministic shader-generated rain/snow remains a visual approximation rather than a native simulation.

The cloud and precipitation fragment pipelines were also checked against the viewer's reversed-Z convention: the opaque world depth clears to 0 and terrain/scenery uses `Greater`/`GreaterEqual`. Both translucent overlays had mistakenly used `LessEqual`, which rejects normal positive reversed depth; they now use `GreaterEqual`. This fixes visibility/depth admission, not native cloud primitive topology or particle behavior.

## Runtime behavior and regression coverage

- **Region precedence:** `Environments::endpoints` now iterates overlapping boxes into distinct local/default slots instead of globally sorting by distance. Local wins for fog/colour; the default independently supplies celestial direction/flags. If no default is present, the recovered constructor fallback is retained rather than using local flags/direction. Streamed selection continues to use `ActiveBoxMap::select_pair` and its hash/load order. New assertions in `client_v12_box_fog_and_priority` cover overlapping default + local records and local-only fallback.
- **Weather selection, timing and rendered approximation:** World-environment update `0x421520` selects rain and snow independently from area flag bits 1 and 2; `WeatherSelection` mirrors that mask. `WeatherClock` matches the `> 33 ms` fixed-step accumulator. `WeatherGpu` now draws regional camera-centred world-space particles with depth/fog in main, reflection and clipped above-water views, while suppressing precipitation in the underwater main camera; it does not claim native particle parity. Separately, `Scene::effect_visible` uses scene-effect `valid_time`; modes 0/1 switch strictly around night factor 0.5 and mode 2 is always eligible. That is placed scene-effect eligibility, not precipitation selection.
- **Fog per view:** `normal_reflected_underwater_and_clipped_views_keep_distinct_regional_fog` covers main/reflection camera fog, always-enabled underwater fog, plane-relative clipped refraction fog, the below-surface air-fog override, and the fact that disabling atmospheric fog does not modify the authored fog endpoints. The fog matrix now includes precipitation and cloud-surface rows: camera table fog in main/reflection, omission from the clipped underwater refraction, and air fog in the above-water secondary view from underwater. Both GPU atmosphere passes receive those same per-view fog bindings; existing terrain/grass/BMD rows keep exponential refraction distinct from table fog.
- **Sky resource selection:** the AutoFamily sky configuration parser resolves its `Resource/sky_list` path, day/night IDs and list entries; the GPU loads the listed panorama/roof resources and uses the client night-factor threshold plus 1000 ms transition. The repeatable survey validates the active ID-to-path mappings against the PCK contents.
- **Above-water visibility:** `ViewSettings::far` controls the projection far plane independently of atmospheric fog. When no explicit setting is saved, the AutoFamily `fog_enable` bit supplies the viewer default; a saved user choice takes precedence. This does not establish native world max distance or every material-specific fog enable path.

## Changed files

- `src/environment.rs` — split local/default selection, preserve serialized bounds for default and local OBBs, and cover bounds/overlap/fallback regressions.
- `src/client_region_map.rs` — regression coverage for the supplied world’s 37906/38176 local overlap and synthetic default-overlap last-match ordering under native hash buckets.
- `src/client_region_stream.rs` — native initial-load/overlap FIFO behavior with stale-candidate attempt accounting; the viewer’s fixed one-attempt quota is explicitly marked approximate because native `+0x534` is dynamically carried.
- `src/fog_matrix.rs` — per-material/pass fog matrix now includes cloud-surface and precipitation main/reflection, clipped-refraction omission and below-surface air-fog rows, with regression coverage.
- `src/client_weather.rs` — native 33 ms weather-object clock plus independently selected rain/snow flag mapping and tests.
- `src/weather_gpu.rs` — deterministic camera-centred world-space rain/snow billboards gated by regional flags, advanced on the 33 ms logic clock, depth-tested/fogged, clipped/admitted in main/reflection/above-water passes, and suppressed when the camera is below a mapped water surface according to parsed masks; explicitly not native particle parity.
- `src/main.rs` — registers timing, cloud-surface, sky-configuration and weather-render modules.
- `src/cloud_surface.rs` — checked native `MOXB` grid/cell/group parser with vertex-index validation and Rust tests; native `.cld` structure was cross-checked against the supplied resource by the Python survey, but Rust tests remain unexecuted without the toolchain.
- `src/cloud_gpu.rs` — client cumulus-textured camera-facing cloud billboards built from indexed `.cld` groups, now selecting the native 4×4 atlas cell from the first vertex tag, with depth testing, fog and main/reflection/refraction submission. Group scale remains approximate; native topology, camera-relative geometry, size/time/color curves, secondary water-mask admission and GPU/runtime validation remain open.
- `src/view_settings.rs` — persist the client `CloudDetail`-equivalent toggle (viewer default on); `src/gpu.rs` applies it to each cloud pass and exposes it in World settings.
- `src/sky_config.rs` — parses AutoFamily sky IDs/list entries and fog defaults; models the 0.5 selector, 1000 ms blend, and no-pop retargeting for interrupted transitions (native interruption semantics remain unverified).
- `src/sky_gpu.rs` — loads configured day/night sky texture sets and carries the scene fog-enable default.
- `src/gpu.rs` — advances the sky and weather clocks once per world frame; dispatches cloud billboards and depth-tested precipitation in main/reflection/refraction views with their pass fog/clip state.
- `tools/region-weather-survey.py` — repeatable client/world evidence survey; validates configured sky IDs and texture resources, reports curated atmosphere-effect placements, and validates the `.cld` grid, group records and all indices. It expects supplied assets under ignored `google_drive/`, staged here but intentionally excluded from Git.
